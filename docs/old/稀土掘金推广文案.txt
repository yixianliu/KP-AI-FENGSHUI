## 缘起：为什么要造这个轮子？

作为开发者，我们常说"不要重复造轮子"。但在传统命理排盘领域，现有的轮子有三个致命缺陷：

| 痛点 | 现状 | 后果 |
|------|------|------|
| **算法不准** | 多数工具用查表法、简化算法，忽略真太阳时修正、立春分界、早晚子时边界 | 换个工具排盘结果都不一样，用户无从判断 |
| **黑盒不可信** | 闭源、云端计算、逻辑不公开 | 只能盲目信任，无法验证、无法复现 |
| **隐私裸奔** | 必须上传出生年月日时、经纬度、性别 | 敏感个人信息流转云端，甚至被用作 AI 训练语料 |

所以我决定：**把轮子重新造一遍，但要造成"可验证、可复现、不上云"的工程级轮子。**

---

## 🎯 产品定位：解决什么问题？

### 1. 算不准 → **天文级精度的本地计算引擎**
- 节气换月：高精度天文算法（非查表），精确到分钟
- 年柱分界：严格按**立春**而非大年初一（符合《子平真诠》《渊海子平》）
- 真太阳时：经度修正 + 均时差计算，还原古法子时（23:00 起）
- 五虎遁/五鼠遁：标准古法推算，无简化近似

### 2. 无法验证 → **算法透明、数据可追溯**
- 核心数据全部来自本地 SQLite 数据库（万年历锚点、干支表、纳音表、神煞表……）
- 计算逻辑纯函数化，输入确定 → 输出确定，便于单元测试锁定
- 100+ 项 pytest 单测，覆盖关键算法节点与万年历锚点

### 3. 隐私担忧 → **彻底本地化，数据不出本机**
- 无网络请求（除非主动开启 AI 解读）
- 出生时间、经纬度、性别全程本地处理
- 离线环境下可完整运行所有排盘功能

### 4. 解读贵/黑盒 → **可选 AI，结构化输出，自带 Key**
- AI 解读完全可选，不配置 Key 不影响核心功能
- 以本地排盘 JSON 为唯一输入，输出结构化报告（格局总评/分项分析/建议）
- 支持 OpenAI/DeepSeek/Qwen 等多模型，本地 ChromaDB 缓存避免重复请求

### 5. 难保存/难展示 → **专业导出，开箱即用**
- 一键导出 PDF/Excel/CSV
- 专业细盘排版：四柱、藏干、十神、纳音、空亡、五行能量、格局、大运流年、十二长生……

### 关键技术决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| **核心算法** | 纯函数式 + Pydantic v2 数据校验 | 无副作用、易测试、强类型、可序列化 |
| **GUI 框架** | PySide6 (Qt) | 原生性能、跨平台、样式系统强、Canvas 绘制九宫格飞星盘 |
| **天文算法** | 自研高精度算法（VSOP87 简化版 + 自研均时差） | 非查表法、精确到分钟、可离线运行 |
| **AI 集成** | LangChain + ChromaDB 本地向量库 | 数据不出本机、支持多模型、RAG 检索可控 |
| **持久化** | SQLite | 零配置、单文件、跨平台、支持并发读 |
| **打包分发** | PyInstaller + 签名 | 免安装 exe、Windows 原生体验 |

## 🧪 质量保障：如何保证"算得准"？

```python
# tests/test_bazi_calculator.py - 关键锚点测试示例
def test_lichun_boundary_year_pillar():
    """立春分界年柱测试：1984-02-04 23:00 前属癸亥年，后属甲子年"""
    # 立春前一天 23:00
    dt1 = datetime(1984, 2, 4, 22, 59, tzinfo=ZoneInfo("Asia/Shanghai"))
    assert bazi_calculator.get_year_pillar(dt1) == "癸亥"
    # 立春当天 00:00
    dt2 = datetime(1984, 2, 4, 0, 0, tzinfo=ZoneInfo("Asia/Shanghai"))
    assert bazi_calculator.get_year_pillar(dt2) == "甲子"

def test_true_solar_time_correction():
    """真太阳时经度修正：北京时间(UTC+8) vs 真太阳时"""
    # 经度 116.4° (北京)，平太阳时 12:00
    # 真太阳时 ≈ 12:00 + 4min × (116.4 - 120) + 均时差
    assert abs(bazi_calculator.true_solar_time(dt, lon=116.4) - expected) < timedelta(minutes=1)
```
